## 二、产品定位

**一句话定位**：一个"记一次就够准"的私密月经记录本——用户只在经期来/走时花 10 秒记录，App 负责算出下一次并提前提醒。

**核心价值主张**：
1. **记得快** —— 经期开始/结束一键记录，10 秒内完成
2. **算得准** —— 基于历史周期的个性化预测，随使用越来越准
3. **不会忘** —— 多节点提醒 + 安卓权限加固，确保提醒能响
4. **看得懂** —— 日历 + 倒计时 + 趋势图，一眼看清周期状态
5. **不外泄** —— 应用锁 + 本地加密 + 零联网，隐私边界最干净

**不做什么（明确边界）**：
- 不做医疗诊断、不提供用药建议（仅"非医疗"提示）
- 不做社交、社区、分享
- 不做云同步、账号体系
- 不做每日强制打卡（不制造焦虑）

## 五、交互流程

### 5.1 首次使用流程
```
启动 → 首启引导（3 步：这是什么 / 怎么记 / 隐私承诺）
     → 设置"上次经期开始日"（可跳过）
     → 申请通知权限（可稍后）
     → 进入首页，展示预测（无历史则显示"记录一次即可开始预测"）
```

### 5.2 记录一次经期（主流程，目标 ≤10 秒）
```
首页 → 点「经期来了」 → 底部弹层（默认今天）
     → 选流量强度（少/中/多，默认"中"）
     → 选痛经程度（无/轻/中/重，默认"无"）
     → 保存 → 日历立即着色 + 自动算出下次预测 + 提示"已记录"
```

### 5.3 结束经期流程
```
首页 → 点「经期结束」 → 默认今天为结束日
     → 校验（结束日不得早于开始日）
     → 保存 → 更新本次经期天数 → 重算平均周期 → 刷新预测
```

### 5.4 补录 / 编辑历史
```
记录Tab → 点某次记录（或日历点某天）→ 编辑弹层
        → 修改开始/结束/流量/痛经 → 保存 → 全局重算
        → 删除记录 → 二次确认 → 全局重算
```

### 5.5 提醒设置与生效
```
设置 → 提醒设置 → 打开"经前预感"(默认提前2天) / 经期开始 / 排卵期 / 排卵日
     → 设定提醒时间（默认 09:00）与免打扰时段
     → 首次开启时弹出"提醒自检"，引导开通知权限、精确闹钟、电池白名单
     → 系统按预测日期准时推送通知
```

### 5.6 异常提示流程（温和不惊吓）
```
预测引擎检测到：周期波动 > 阈值 / 经期 > 10天或 < 2天 / 标记异常出血
  → 首页出现"关注"标签（黄色、非红色告警）
  → 点开显示中性文案："本次周期与你的平均值差异较大，建议留意；若持续异常可咨询医生。"
  → 底部固定"以上信息仅供参考，不作为医疗诊断依据。"
```

### 5.7 应用锁流程
```
启动/切后台返回 → 生物识别（可用时优先）→ 失败则密码/图案
  → 5 次失败冷却 30 秒
  → 后台停留 > 30 秒自动锁定
```

## 六、关键设计决策与权衡取舍

### 6.1 定位：面向全年龄段通用，而非单一人群
- **理由**：市场最大、扩展性最好，避免第一版就锁死细分人群。
- **权衡**：UI 需兼顾 20 岁与 50 岁用户，不能过度少女化；因此选"温柔治愈"而非"粉嫩插画"。

### 6.2 主场景：经期集中记录，而非每日打卡
- **理由**：用户真实行为是"来/走时记一次"；强行每日打卡会制造焦虑、加速流失。
- **权衡**：数据维度少于竞品（无每日症状流水），但录入负担极低、完成率高。

### 6.3 核心闭环：记录 + 预测 + 提醒
- **理由**：三者构成不可替代的价值循环；缺预测则无预测感，缺提醒则无回访理由。
- **权衡**：开发量比"纯记录"大，需实现算法与通知模块。

### 6.4 记录字段：4 项最小必要集
- **理由**：字段越少越不容易放弃；流量/痛经是预测之外最有价值、最易录的两项。
- **权衡**：不做体温、白带、用药等专业维度，失去备孕深度用户。

### 6.5 预测算法：两段式（规则兜底 + 智能增强）
- **理由**：选择智能建模，但新用户无历史数据会"冷启动"。纯规则不准、纯智能无数据，两段式兼顾。
- **权衡**：需维护两套逻辑与切换阈值（<3 个周期走规则，≥3 走加权，≥6 启用智能修正）。

### 6.6 提醒：多节点 + 可自定义
- **理由**：不同用户需要的节点不同，必须可关可调。
- **权衡**：设置项变多，需要默认值足够聪明（默认只开"经前预感"和"经期开始"两项）。

### 6.7 隐私：应用锁 + 本地加密 + 零联网
- **理由**：月经数据是敏感个人信息，隐私即信任。
- **权衡**：放弃云同步能力，且必须做好"换机即丢"的心理预期管理。

### 6.8 同步：不做账号与云同步
- **理由**：明确选择不做；同时也让"数据不出本机"的承诺 100% 成立。
- **权衡**：**换机/卸载/丢失 = 数据全丢**，已列高风险项。

### 6.9 平台与技术栈：Flutter → Android APK
- **理由**：一套代码保证 UI 一致与动效品质；未来扩展 iOS/鸿蒙成本最低。
- **权衡**：APK 体积约 15–25MB，大于纯原生轻量方案。

### 6.10 首页形态：日历 + 倒计时卡
- **理由**：日历满足"看历史/补录"，倒计时卡满足"预测感/情绪价值"。
- **权衡**：首页信息密度上升，需严格分层。

### 6.11 视觉：温柔治愈系
- **理由**：月经话题天然带情绪，暖粉 + 留白 + 圆润卡片能传递"安全感"。
- **权衡**：暖色系在强光下对比度需特别处理。

### 6.12 无障碍：全面适配
- **理由**：目标用户覆盖 40+，字号与色弱是真实需求。
- **权衡**：开发与设计成本上升。落地细节：流量强度用"图标 + 数量纹理 + 文字"三重编码。

### 6.13 异常处理：标记 + 温和提示，不做诊断
- **理由**：体现价值又守住合规边界；医疗诊断需资质，越界有法律风险。

### 6.14 提醒可靠性加固
- **理由**：安卓省电策略会杀后台，提醒不响=核心功能失效。
- **权衡**：需引导用户开多项系统权限，引导流程变长。

### 6.15 不做备份导出与不做合规文件
- **理由**：按需求决策，减少首版范围。
- **权衡**：两项均为高风险，见第九章。

### 6.16 统计：基础统计 + 趋势图
- **理由**：足够让用户"看出变化"，又不越界做健康评分。

## 七、数据模型（本地 SQLite / SQLCipher 加密）

```
表 cycle（经期记录）
  id            INTEGER PK
  start_date    TEXT (ISO yyyy-MM-dd)      必填
  end_date      TEXT                        可空（未结束则接续预测）
  flow_level    INTEGER (0=少,1=中,2=多)     默认 1
  cramp_level   INTEGER (0=无,1=轻,中,重)     默认 0
  note          TEXT                        预留
  created_at    TEXT
  updated_at    TEXT

表 settings（键值）
  key           TEXT PK
  value         TEXT
  -- 例：avg_cycle=28, avg_period=5, remind_before_days=2,
  --     lock_type=biometric, auto_lock_seconds=30, font_scale=1.0,
  --     dark_mode=auto, colorblind_mode=0

表 anomaly（异常标记，可选）
  id / cycle_id / type(irregular|too_long|too_short|abnormal_bleeding) / marked_at
```

**派生计算（内存中实时算，不落库）**：
- 平均周期长度 = 相邻两次 start_date 差的均值（加权近 6 次）
- 平均经期天数 = end_date - start_date + 1 的均值
- 下次经期 = 最近一次 start_date + 平均周期
- 排卵日 ≈ 下次经期 - 14 天；易孕窗口 = 排卵日 ±5 天

## 八、技术架构（Flutter / Android）

| 层 | 选型 | 说明 |
|---|---|---|
| UI | Flutter + Material 3 定制主题 | 暖粉色板 + 圆润卡片 |
| 状态管理 | Riverpod | 轻量、可测试 |
| 本地存储 | sqflite + SQLCipher | 整库加密（AES-256），密钥由 Android Keystore 保护 |
| 应用锁 | local_auth（生物识别）+ 自研密码/图案 | 失败降级、冷却、自动锁 |
| 通知 | flutter_local_notifications + AlarmManager（精确闹钟） | Android 12+ 精确闹钟权限、Doze 白名单 |
| 权限引导 | permission_handler + 自定义自检页 | 通知、精确闹钟、电池优化 |
| 图表 | fl_chart | 趋势折线/柱状图 |
| 工程化 | 分层架构（presentation / domain / data） | 便于后续接入备份导出、云同步 |

**安全要点**：密钥不经明文落盘；后台截图保护用 FLAG_SECURE；日志不输出敏感数据；首版不申请 INTERNET 权限。

## 九、风险清单

| 级别 | 风险项 | 影响 | 建议处置 |
|---|---|---|---|
| 高 | 无任何备份导出 | 卸载/换机/丢失 = 数据永久丢失 | V1.1 补「加密备份文件导出/导入」 |
| 高 | 无隐私政策/免责声明 | 上架驳回/下架；《个人信息保护法》合规风险 | 上架前必配 |
| 中 | 安卓提醒被系统杀 | 核心提醒功能失效 | 自检页 + 权限引导 |
| 中 | 智能预测冷启动不准 | 新用户前 1–2 月偏差大 | 两段式算法 + 置信度提示 |
| 低 | APK 体积偏大 | 下载门槛略高 | R8/资源压缩、按 ABI 分包 |
| 低 | 暖色系对比度不足 | 强光下可读性差 | 主色低饱和 + 文字深灰 |

- [ ] 可安装 APK，冷启动 < 2s，无崩溃
