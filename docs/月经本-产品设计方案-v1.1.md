## 二、产品定位

**一句话定位**：一个「记一次就够准」的私密月经记录本——用户只在经期来/走时花 10 秒记录，App 负责算出下一次并提前提醒。

**核心价值**：记得快 · 算得准 · 不会忘 · 看得懂 · 不外泄

**明确不做**：医疗诊断 / 用药建议、社交与分享、云同步与账号、每日强制打卡、健康科普、备份导出。

## 五、交互流程

### 5.1 首次使用
```
启动 → 引导（这是什么 / 怎么记 / 隐私承诺）
     → 填写「上次经期开始日」（可跳过）
     → 填写「通常周期天数」（默认 28，提供 21–35 滑杆）
     → 申请通知权限（可稍后）
     → 进入首页：立即给出首次预测 + 标注「置信度：低」
```

### 5.2 记录一次经期（≤10 秒）
```
点「经期来了」→ 弹层（默认今天）
→ 选整次流量概览（少/中/多，默认「中」）
→ 选整次痛经概览（无/轻/中/重，默认「无」）
→ 保存 → 日历着色 + 重算预测 + 排定提醒
→ 首页切换为「经期第 1 天」状态
```

### 5.3 经期进行中（新增状态机）
```
每天：首页显示「经期第 N 天」
用户可随时点日历某天 → 补充/修改当日流量与痛经（选填，不提醒、不强制）
结束日 = 用户点「经期结束」的那一天（唯一真值来源）
超过「预期经期天数」后：每日一次温和提醒「经期还在继续吗？」
  → 点「已结束」→ 记录结束日
  → 点「仍在继续」→ 次日再问
  → 不点 → 继续每日问一次，绝不自动结束
```

### 5.4 结束经期
```
点「经期结束」→ 默认今天 → 校验（不早于开始日）
→ 保存 → 计算本次经期天数 → 重算平均周期 → 刷新预测与提醒
```

### 5.5 补录 / 编辑历史
```
记录 Tab → 点某次记录 → 修改开始/结束/整次概览/每日详情 → 全局重算
删除 → 二次确认 → 全局重算
```

### 5.6 异常提示（温和、不惊吓）
```
触发条件：周期波动 > 7 天 或 经期 > 8 天 或 < 2 天，且连续 2 次
→ 首页出现「关注」标签（琥珀色，非红色告警）
→ 文案：「近两次周期与你的平均值差异较大，建议留意；若持续异常可咨询医生。」
→ 固定兜底：「以上信息仅供参考，不作为医疗诊断依据。」
```

### 5.7 应用锁
```
启动 / 切后台返回 → 生物识别（指纹·面容）
  → 不可用（无硬件 / 未录入 / 临时失败）→ 回退系统锁屏凭据（PIN·图案·密码）
  → 成功解锁
  → 后台停留 > 30 秒自动锁定
```

## 六、关键设计决策与权衡取舍

### 6.1 记录粒度：按「次」+ 可选每日（v1.1 修正）
- **理由**：整次一条记录会让流量/痛经失真（这两项在经期过程中逐日变化）；但强制每日填写又违背「不打卡」定位。折中为**主记录存整次概览，每日详情选填**。
- **取值规则**：展示时优先取当日详情，未填则回落到整次概览。
- **权衡**：多一张 `cycle_day` 表与一个每日编辑页，开发量小幅上升；换来数据准确性与「不强制」的体验。

### 6.2 应用锁：仅生物识别 + 回退系统凭据（v1.1 修正）
- **理由**：不设独立 App 密码，就**不存在「忘记密码」这个死结**；回退到手机系统锁屏凭据，用户本来就记得。
- **权衡（必须知晓）**：安卓 Keystore 密钥与设备凭据绑定，**用户一旦移除手机锁屏密码/指纹，已加密数据可能无法解密**。这是该方案的固有风险，缓解方式：设置页明确提示「请勿移除手机锁屏密码，否则数据将无法访问」。
- **权衡 2**：无指纹的旧设备将直接使用系统 PIN/图案解锁，安全性仍高于无锁。

### 6.3 经期进行中：永不自动结束（v1.1 新增）
- **理由**：自动补结束日会写入**假数据**，污染预测模型；「经期第 N 天」+ 每日温和提醒既保证数据真实，又解决用户忘记操作的问题。
- **权衡**：若用户长期不理，进行中状态会一直挂着；用每日一次的温和提醒（可在设置中关闭）收敛。

### 6.4 排卵期保留但标注「日历法估算」
- **理由**：你选择保留并默认开启。但仅用「下次经期 −14 天」推算，对周期不规律用户误差大。
- **权衡**：保留功能与提醒，但**必须在 UI 上标注估算方法与误差提示**，避免用户误当作备孕依据（本产品明确非备孕定位）。

### 6.5 冷启动：引导用户填写
- **理由**：比「默认 28 天」更准，首月即可给出有意义预测，避免新用户体验落差。
- **权衡**：首启多一步填写（约 5 秒），可能轻微影响激活率；提供默认值与「跳过」降低摩擦。

### 6.6 异常判定：波动 > 7 天且连续 2 次
- **理由**：单次波动很常见，连续 2 次才提示可显著降低误报；阈值 7 天兼顾敏感度与稳定性。
- **权衡**：真实异常可能延后一个周期才被发现；对健康类产品而言「少误报」优于「早发现」（且我们不做诊断）。

### 6.7 提醒：四个节点全部默认开启
- **理由**：你的选择，保证新用户第一时间感受到提醒价值。
- **权衡**：提醒较频繁，可能引发关闭通知权限。缓解：每个节点可独立关闭、支持免打扰时段、并在设置页提供「一键减少提醒」。

### 6.8 流量编码：水滴数量三重编码
- **理由**：解决「温柔治愈粉 × 色弱不可辨」的冲突——用 1/2/3 滴水滴图标 + 数字 + 文字，颜色仅辅助。
- **权衡**：视觉上不如纯色块简洁，换来确定性的无障碍可辨识。

### 6.9 备份仍不做（风险已确认接受）
- **理由**：你的决定，首版范围最小。
- **权衡**：**卸载 / 换机 / 丢机 = 数据永久丢失**。这是本方案唯一无法技术缓解的高风险项，只能靠用户自觉。架构上已为「加密文件导出」预留位置，随时可低成本补做。

### 6.10 分发范围：仅自用/内部分发
- **理由**：你的选择，因此合规文件暂缓。
- **权衡**：不进应用市场，就不需要强制隐私政策与审核；但**建议随包附一份最简隐私说明**（说明数据仅存本地、不联网、不上传），成本极低且能避免误解。

### 6.11 平台与技术栈：Flutter → Android APK，minSdk 26
- **理由**：minSdk 26 覆盖约 97% 设备，且通知渠道（Android 8.0 引入）、生物识别 API 均可正常支持，无需为老设备写大量兼容代码。
- **权衡**：约 3% 的 Android 6/7 老设备无法安装；精确闹钟（API 31+）在低版本上用 AlarmManager 兼容实现。

### 6.12 其余沿用决策
- 全年龄段通用定位、经期集中记录、记录+预测+提醒闭环、4 项最小字段、隐私零联网、无账号无同步、日历+倒计时卡首页、温柔治愈视觉、全面无障碍、基础统计+趋势图 —— 理由与权衡同 v1.0 第 6.1–6.16 节。

## 七、数据模型（本地 SQLite / SQLCipher 加密）

```
表 cycle（经期主记录 · 按「次」）
  id             INTEGER PK
  start_date     TEXT (yyyy-MM-dd)      必填
  end_date       TEXT                   可空 = 经期进行中
  overall_flow   INTEGER (0=少,1=中,2=多)   默认 1
  overall_cramp  INTEGER (0=无,1=轻,2=中,3=重) 默认 0
  note           TEXT                   预留
  created_at     TEXT
  updated_at     TEXT

表 cycle_day（经期每日详情 · 选填）
  id             INTEGER PK
  cycle_id       INTEGER FK → cycle(id) ON DELETE CASCADE
  day_index      INTEGER                经期第几天（从 1 起）
  date           TEXT (yyyy-MM-dd)
  flow_level     INTEGER                可空 = 未填写
  cramp_level    INTEGER                可空 = 未填写
  updated_at     TEXT
  UNIQUE(cycle_id, date)

表 settings（键值）
  key TEXT PK / value TEXT
  -- default_cycle_len, default_period_len, remind_pre_period(bool,int),
  -- remind_period_start, remind_fertile, remind_ovulation,
  -- remind_hour, remind_minute, dnd_start, dnd_end,
  -- auto_lock_seconds, font_scale, dark_mode, colorblind_mode

表 anomaly（异常标记）
  id / cycle_id / type(irregular|too_long|too_short) / marked_at
```

**取值规则**：展示某天流量/痛经时，`cycle_day` 有值则用之，否则回落到 `cycle.overall_*`。

**派生计算（内存实时算，不落库）**：
- 周期长度序列 = 相邻 `start_date` 之差
- 平均周期 = 加权平均（近 6 次，近期权重高；≥3 次时剔除最大最小值各一个）
- 平均经期天数 = 已完成周期的 `end_date - start_date + 1` 均值
- 下次经期 = 最近 `start_date` + 平均周期
- 排卵日 ≈ 下次经期 − 14 天；易孕窗口 = 排卵日 ±5 天（**标注日历法估算**）

**预测算法分级（两段式落地参数）**：

| 已有完整周期数 | 算法 | 置信度 |
|---|---|---|
| 0 | 用首启填写的周期天数 / 经期天数 | 低 |
| 1–2 | 简单平均（用户填写值兜底） | 低 |
| 3–5 | 近 3–6 次加权平均 + 离群剔除（去最大最小） | 中 |
| ≥6 | 加权平均 + 标准差修正 + 连续同向偏移微调 | 高 |

置信度在首页倒计时卡上明示，低置信度时文案为「预测仅供参考，记录越多越准」。

## 九、风险清单

| 级别 | 风险项 | 影响 | 处置 |
|---|---|---|---|
| 高 | 无任何备份/导出 | 卸载、换机、丢机 = 数据永久丢失 | 已确认接受；架构预留导出位置，随时可补 |
| 中 | 移除手机锁屏密码导致加密数据不可解密 | 数据永久无法访问 | 设置页强提示「请勿移除手机锁屏密码」 |
| 中 | 安卓省电策略杀后台 | 提醒不响 | 自检页 + 权限引导 + 电池白名单 |
| 中 | 排卵期日历法误差大 | 误导用户 | UI 明确标注「日历法估算，仅供参考」 |
| 中 | 提醒默认全开导致关闭通知权限 | 提醒功能整体失效 | 节点可独立关闭 + 免打扰时段 + 「一键减少提醒」 |
| 低 | 无指纹旧设备只能用系统 PIN | 体验略降 | 接受，安全性仍高于无锁 |
| 低 | 暖色系强光下对比度 | 可读性下降 | 主色低饱和 + 深灰文字 + 水滴三重编码 |
| 低 | APK 体积 | 下载门槛 | R8 压缩 + 按 ABI 分包 |

> 原「合规文件」风险因分发范围定为**仅自用/内部分发**而降级：无需强制上架材料，建议随包附最简隐私说明。
